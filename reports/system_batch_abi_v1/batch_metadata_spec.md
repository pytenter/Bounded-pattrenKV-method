# Batch Metadata Spec

`PatternKVBatchMetadata` is the proposed kernel-facing metadata object.

## Tensors

| Field | Shape | Dtype | Host generated by | GPU read by | Update time |
|---|---:|---|---|---|---|
| `request_indptr` | `[B+1]` | `int32` | backend from request page tables | decode kernel | each batch |
| `seq_lens` | `[B]` | `int32` | scheduler/backend | QK/V decode | each batch |
| `num_pages` | `[B]` | `int32` | backend | decode kernel | each batch |
| `k_page_table` | `[total_pages]` | `int32` | allocator/backend | QK decode | when batch/page table changes |
| `v2_page_table` | `[total_pages]` | `int32` | allocator/backend | V decode | when batch/page table changes |
| `v4_page_table` | `[total_pages]` | `int32` | allocator/backend | V decode | when batch/page table changes |
| `metadata_page_table` | `[total_pages]` | `int32` | allocator/backend | QK/V decode | when batch/page table changes |
| `precision_bitmap` | `[metadata_pages,4]` | `uint32` | cache writer/selector commit | V routing | append/pack page update |
| `v2_counts` | `[metadata_pages]` | `uint16` | cache writer | V routing | append/pack page update |
| `v4_counts` | `[metadata_pages]` | `uint16` | cache writer | V routing | append/pack page update |
| `selector_state_offsets` | `[B]` | `int32` | backend/cache manager | selector or future append kernels | request admission/update |
| `slot_mapping` | `[B]` or `[tokens]` | `int32` | scheduler/allocator | append/write path | each decode/extend step |

Optional fields:

- `v2_prefix_counts`: `[metadata_pages,129] uint16`
- `v4_prefix_counts`: derived from logical offset and `v2_prefix_counts`, or stored symmetrically
- `last_page_len`: `[B] int32`, derivable from `seq_lens` but useful for FlashInfer-like adapters

## Host/GPU Ownership

- Host/backend builds request tables from scheduler and allocator state.
- Cache writer updates precision bits and stream counts when a page receives new packed tokens.
- GPU decode reads only stable metadata for the current launch.
- A future GPU append path may update page-local counts, but the MVP can keep writes host-orchestrated.

## Invariants

- `request_indptr[B] == total_pages`.
- `num_pages[b] == request_indptr[b+1] - request_indptr[b]`.
- Every page table id is a physical page id in its corresponding pool or a sentinel for empty stream pages.
- For every valid logical page, `v2_counts + v4_counts == valid_tokens`.
- `precision_bitmap` and V2/V4 compact metadata agree with counts.
